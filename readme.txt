=== Dompekin Delivery ===
Requires at least: 6.0
Requires PHP: 7.4
Stable tag: 0.7.2

Управляемый вызов курьера Достависты после принятия оплаченного заказа.

== Что делает ==
* Реагирует на принятие заказа рестораном (мета _dp_stage = cooking).
* Проверяет: плагин включён, есть токен, заказ оплачен, доставка ещё не создана, заказ не самовывоз.
* Вызывает курьера через cms-module 1.0 — тот же контур, что у официального плагина, токен берётся из его таблицы.
* Выполняет calculate-order, затем create-order.
* Транспорт: пеший (6) до порога из настроек, иначе авто (7) — строго по расстоянию.
* Сохраняет ID заявки и защищает от повторного создания (атомарная резервация в базе).
* При сбое геокодера заявку НЕ создаёт: заказ помечается blocked, причина пишется в заметку. Повтор — кнопкой в панели после починки.
* При неизвестном результате не повторяет запрос автоматически: нужна сверка в кабинете Достависты.
* Принимает уведомления по адресу /wp-json/dpd/v1/callback с проверкой HMAC.

== Чего НЕ делает ==
* Не создаёт доставку без подтверждённой оплаты и принятия.
* Не вызывает курьера по самовывозу.
* Не завершает заказ автоматически по событию «доставлено»: событие фиксируется, решение за оператором.
* Не ограничивает стоимость доставки (решение владельца).
* Не возвращает деньги при отмене: возврат в ЮKassa вручную.

== Режимы ==
* «Кто считает цену»: метод официального плагина (по умолчанию) или наш тариф.
* «Кто создаёт заявки»: наш плагин (по умолчанию) или официальный плагин.
* Официальный плагин нельзя удалять: он держит callback и таблицу с токеном. Допустима только деактивация.

== Установка ==
1. WooCommerce → Dompekin Delivery.
2. Заполнить адрес и телефон ресторана.
3. Выбрать среду. Для боевой нужен вход в визард официального плагина: токен появляется в его таблице.
4. Включить автовызов и сохранить.
5. Нажать «Привести зону доставки в порядок»: в зоне остаётся один метод доставки.
6. Перед первым тестом убедиться, что старый автовызов темы выключен.

== Данные ==
Токены хранятся в таблице настроек WordPress в открытом виде. Доступ к базе должен быть ограничен. Токены, адреса и телефоны не пишутся в отчёты и не передаются в чат.
